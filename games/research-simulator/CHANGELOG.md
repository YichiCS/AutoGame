# 科研模拟器 · 更新日志

每次更新在 `research-simulator-v<版本号>` 分支上完成，合并回 main 后上线。新版本写在最上面。

## v0.2.0 — 2026-10-18

四个减少操作量的新功能。旧存档照常能读：新设置读档时补默认值，默认行为和以前完全一样。

- **出路与到期**（「方针」栏新卡片）：本科生想读研、硕士生想读博、博士生申请答辩、博士后合同到期时怎么处理，可以按身份分别设置——「跟随托管」（默认，和以前一样看「托管 → 学生 · 请求和去留」）、「每次问我」（全部托管时也照样问），或者一条自动规则：
  - 本科生：按水平（够博士水平的读博，其余读硕）/ 只留尖子（够博士水平的读博，其余放走）/ 都读博 / 都读硕 / 都放走
  - 硕士生：留下读博 / 都去工作
  - 博士生：直接答辩 / 先延期一年 / 先延期两年（按每个人已经延期过几次算；读满 6.5 年不能再拖的直接答辩）
  - 博士后：续约一次 / 续约两次（按续约过几次算，续满就祝前程似锦）/ 到期放走

  自动处理用的就是弹窗里原来的选项，心情、信任、工资、成长轨迹都和亲手选一样，动态里记一条「[出路方针] …」；规则用不了时退回托管设置。博士毕业、博后到期的弹窗里会写已经延期 / 续约过几次（旧存档的博后按合同长度估算续约次数）。
- **持续招人**（「成员」页工具栏下的两个开关）：「持续招本科生」「持续招博士后」打开后，到了能再招的时候自动发起下一轮——本科生和手动招募一样每 120 天一轮，博士后每 120 天发一次招聘广告。名单照样弹出来由你挑（全部托管时也是）；工位满了、或者加上一份博后工资后经费撑不到 18 个月，就先暂停并在动态里说明，条件恢复后自动接着招。
- **招人名单**（「方针」栏新卡片）：研究生招生季（博士 / 硕士）、本科生、博士后的候选人名单弹出来以后，按身份设成「跟随托管」（默认）、「我自己挑」或「从高到低招满」——按总评从高到低录用（招生季没面试的按估计范围的中间值），直到名额（博士 / 硕士名额、这次的录用上限）、空工位（招生季算上一年内要毕业离开的人）或经费（加上工资后至少还能撑 18 个月）用满，动态里记一条「[自动招满] …」列出招了谁、为什么停。「持续招人」发起的名单只有设成「从高到低招满」才自动录用。
- **工位分配顺序**（「方针」）：工位不够时谁先坐——先到先得（默认，就是以前的分法：已经有工位的人不会被挤掉，空位按身份、入学早晚分）/ 职位优先 / 能力优先（按总评）/ 资历优先（按进组先后）。改了马上重新分配，之后有人进组、每月初也按这个顺序排；谁让出了工位会记在动态里。被你「收回工位」的人不参与排队。
- 托管里「学生 · 请求和去留」「招人」两类的说明、托管页底部、事件和名单弹窗的提示、玩法说明都相应更新，告诉玩家可以去「方针」里按身份细调。

## v0.1.0 — 2026-10-18

收录进 AutoGame 游戏厅。原仓库 [YichiCS/Research-Simulator](https://github.com/YichiCS/Research-Simulator) 用 git subtree 导入，保留了全部提交历史。

- 接入游戏厅：`game.json`、存档适配器 `save-adapter.js`（游戏厅里显示实验室 / 读博进度；从游戏厅导入存档时不会触发离线快进）、游戏内悬浮标签。
- 存档位置不变（`research-sim-save-v1`、`research-sim-settings-v1`）：在原地址 yichics.github.io/Research-Simulator/ 玩出的存档，从游戏厅打开时直接就在。
- 在线游玩地址改为 <https://yichics.github.io/AutoGame/games/research-simulator/>。

收录时已有的内容（原仓库的开发记录）：

- 初始可玩版本：经营实验室，申请基金、招生、发论文、Tenure / 非升即走考核，北美和中国两种职业体系。
- 课题组（子方向）系统；学校库、按贡献署名、22 个新随机事件。
- 博士阶段：从博士一年级开始，读完博士凭成果找教职；导师行为带随机性。
- 研究方向体系「领域 → 方向 → 子方向」；参考 ccfddl 收录 230 多个会议期刊，支持跨方向投稿。
- 小组规则、工位扩到 32 个、跳槽、青年教师带团队加入、算力「水管」模型、统计页、托管细分。
- 招生面试排序、会议出差「只派一个代表」、更多经费来源、时间检验奖（Test of Time）。
- 学生信息卡、二级导航、论文筛选；学生能力改为正态分布、每年按潜力成长。
